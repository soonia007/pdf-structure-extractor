# Template: เรียนรู้จาก PDF ตัวอย่าง แล้วจำได้เองครั้งต่อไป

แทนที่จะเขียน spec เอง (ดู [FIELDS.md](FIELDS.md)) ให้โปรแกรม **เรียนรู้** จาก PDF ตัวอย่าง
ที่เป็นเอกสารแบบเดียวกัน เช่น ใบแจ้งหนี้จากผู้ขายรายเดียวกันหลาย ๆ ใบ

```
 PDF ตัวอย่าง 1..n ──► observe ──► หา label:value, ตาราง, หัวข้อ, ชนิดข้อมูล
                                          │
                                          ▼
                          build template (รวมทุกตัวอย่าง)
                          ├─ ค่าที่ "เปลี่ยน" ทุกใบ  → fields (ตัวแปร)
                          ├─ ข้อความที่ "เหมือนเดิม" ทุกใบ → anchors (ใช้จำเอกสาร)
                          └─ ตารางที่หัวคอลัมน์ตรงกัน  → table field
                                          │
                                          ▼
                     templates/<name>.template.json   (JSON อ่านได้ เก็บใน git ได้)
                                          │
 PDF ใหม่ ──► match (คะแนนจาก anchors) ──► ใช้ template ที่คะแนนสูงสุด ──► fields
```

## คำสั่ง

```bash
# 1) เรียนรู้จากตัวอย่าง (ยิ่งหลายใบยิ่งแม่น แนะนำอย่างน้อย 2-3 ใบ)
pdfstruct template learn acme_invoice inv1.pdf inv2.pdf --description "ใบแจ้งหนี้ ACME"

# 2) เพิ่มตัวอย่างภายหลัง ระบบจะเรียนรู้ใหม่จากตัวอย่างทั้งหมด (ไฟล์ซ้ำจะถูกข้าม)
pdfstruct template learn acme_invoice inv3.pdf

# 3) ดู / แก้ spec ที่เรียนรู้ได้
pdfstruct template show acme_invoice > acme.yaml      # แก้ชื่อตัวแปร ชนิดข้อมูล required ได้ตามต้องการ
pdfstruct template set-spec acme_invoice acme.yaml    # ใช้ spec ที่แก้เอง (การเรียนรู้ครั้งต่อไปจะไม่ทับ)

# 4) จำเอกสารใหม่และดึงค่าอัตโนมัติ
pdfstruct template match new.pdf                      # ดูคะแนนเทียบทุก template
pdfstruct new.pdf --auto-template --fields-only --pretty
pdfstruct ./inbox --auto-template --fields-only -o ./out   # ทั้งโฟลเดอร์ (แต่ละไฟล์เลือก template ของตัวเอง)

pdfstruct template list
pdfstruct template delete acme_invoice
```

ตัวเลือก `--store DIR` (หรือตัวแปรแวดล้อม `PDFSTRUCT_TEMPLATES`) ใช้กำหนดโฟลเดอร์เก็บ template (ค่าเริ่มต้น `./templates`)
และ `--threshold 0.6` คือคะแนนขั้นต่ำที่จะถือว่าเอกสารตรงกับ template

```python
from pdfstruct import TemplateStore, extract, extract_auto

store = TemplateStore("templates")
store.learn("acme_invoice", [extract("inv1.pdf"), extract("inv2.pdf")])
doc = extract_auto("new.pdf", store)
doc.extraction.template, doc.extraction.template_score   # ('acme_invoice', 1.0)
doc.fields["grand_total"].value                          # 10.0
```

## เรียนรู้อย่างไร

ระบบอ่านหน้าเอกสารเป็น **บรรทัด** และแยกแต่ละบรรทัดเป็น **ชิ้น (segment)** ตรงที่มีช่องว่างกว้าง
จึงรู้ว่าข้อความไหนเป็นป้าย และค่าอยู่ตรงไหนของป้าย:

| รูปแบบในเอกสาร | ตัวอย่าง | ตำแหน่ง (`position`) |
|----------------|----------|---------------------|
| ป้ายกับค่าอยู่ในชิ้นเดียวกัน | `Invoice No: INV-001`, `Tax ID 0105556123456` | `same-line` |
| ค่าอยู่ทางขวาของป้าย (มีช่องว่างกว้าง) | `Invoice No:` ······ `INV-001` &nbsp; `Date:` ······ `05/01/2026` | `right` |
| ค่าอยู่ใต้ป้าย / แถวป้ายอยู่เหนือแถวค่า | `PO Number` &nbsp; `Payment Terms` (แถวล่าง) `PO-7781` &nbsp; `Net 30` | `below` |
| ป้ายภาษาไทยไม่มีโคลอน | `ชื่อ-นามสกุล นายสมชาย ใจดี` | `same-line` / `right` |
| กล่องตารางเล็ก ๆ แบบป้าย/ค่า | ตาราง 2 แถว (ป้าย / ค่า) หรือ 2 คอลัมน์ | `below` / `right` |

| ขั้น | กฎ |
|------|----|
| **แยกป้ายออกจากค่า** | (1) ป้ายลงท้ายด้วย `:` (2) ป้ายเป็นตัวหนาแต่ค่าไม่หนา (3) อยู่ในพจนานุกรมป้ายไทยกว่า 90 คำ (4) **ข้อความที่เหมือนกันทุกตัวอย่างคือป้าย ส่วนที่เปลี่ยนคือค่า** ข้อนี้ใช้ได้กับเอกสารสแกนที่ไม่มีข้อมูลตัวหนา (ระบบเก็บไว้แค่ hash ของข้อความ ไม่เก็บข้อความจริง) |
| **จับคู่ป้ายแบบให้คะแนน** | ป้ายตรงทั้งคำได้คะแนนสูงกว่าป้ายที่เป็นส่วนหนึ่งของคำอื่น เช่น `Date` จะไม่ไปเอาค่าของ `Due Date` และ `Total` จะไม่ไปเอาค่าของ `Subtotal` |
| **ตำแหน่งที่เรียนรู้** | ระบบจำว่าค่าอยู่ขวาหรือใต้ป้าย (`position`) แล้วลองตำแหน่งนั้นก่อน |
| **ชนิดข้อมูล** | date → boolean → number/integer → string (เลขยาว 10 หลักขึ้นไปถือเป็น string) |
| **รูปแบบ (pattern)** | อีเมล, เลขบัตรประชาชน/เบอร์โทร (เก็บจำนวนหลักแต่ละกลุ่ม เช่น `\d-\d{4}-\d{5}-\d{2}-\d`), รหัส เช่น `INV-2026-001` → `[A-Z]+\-\d+\-\d+` |
| **ตาราง** | ตารางมีเส้น, **ตารางไม่มีเส้น** (หัวตาราง + แถวที่จัดแนวตรงกันและมีตัวเลข หยุดเมื่อเจอบรรทัดยอดรวม) และ **ตารางที่ต่อหน้าถัดไป** แม้หน้าถัดไปไม่มีหัวตาราง |
| **ชื่อตัวแปร** | ป้ายภาษาอังกฤษแปลงเป็น `snake_case` (`VAT 7%` → `vat_7`) ส่วนป้ายภาษาไทยใช้พจนานุกรม (`เลขประจำตัวประชาชน` → `citizen_id`, `อีเมล` → `email`) |
| **ความมั่นใจ** | ทุกค่ามี `confidence` 0–1 จากวิธีที่หาเจอและคุณภาพการจับคู่ป้าย (และความมั่นใจของ OCR ถ้าเป็นหน้าสแกน) ในแอป ค่าที่ต่ำกว่า 75% จะมีป้าย "ควรตรวจ" |
| **เอกสารสแกน** | ใช้ OCR อัตโนมัติ (ดู [OCR.md](OCR.md)) แล้วเรียนรู้ด้วยวิธีเดียวกัน |

### ผลวัดบนชุดเอกสารทดสอบ (เรียนรู้จาก 2 ใบ แล้วอ่านใบที่ 3 ที่ไม่เคยเห็น)

| เอกสาร | ก่อนปรับ | หลังปรับ |
|--------|---------|---------|
| ใบแจ้งหนี้ (ป้ายคู่, ค่าห่างป้าย, แถวป้าย/แถวค่า, ตารางไม่มีเส้น) | 3/10 (ค่าผิดหลายตัว) | **10/10** |
| แบบฟอร์มภาษาไทย (ไม่มีโคลอน, เลขบัตร, เบอร์โทร, อีเมล) | 3/6 | **6/6** |
| ใบแจ้งหนี้ที่เป็นภาพสแกน | 0/10 | **10/10** |
| ตารางยาว 2 หน้า | หน้าแรกเท่านั้น | **50/50 แถว** |

ดูวิธีวัดได้ที่ `python tests/measure.py --scanned` และมี test กันไม่ให้คะแนนลดลงใน `tests/test_learning_quality.py`

## ความปลอดภัยและความเสถียร

- **ไม่เก็บค่าจริงของเอกสาร** ไฟล์ template เก็บเฉพาะ hash ของค่า, ชนิด, และ pattern
  (มี test ยืนยัน) จึงเก็บใน git หรือแชร์ได้โดยไม่รั่วข้อมูลลูกค้า แต่ anchors (ข้อความคงที่) ยังอยู่ในไฟล์
- บันทึกไฟล์แบบ atomic (เขียนไฟล์ชั่วคราวก่อนแล้วจึงแทนที่) ถ้าโปรแกรมล่มกลางทาง template เดิมไม่เสีย
- ไฟล์ template ที่เสียจะถูกข้ามตอน `list`/`match` ไม่ทำให้ทั้งระบบล้ม
- ชื่อ template ถูกตรวจ (กัน path traversal เช่น `../`)
- spec ที่แก้มือ (`set-spec`) จะไม่ถูกการเรียนรู้ทับ แต่ anchors และตัวอย่างยังอัปเดตตามปกติ
- ผลเป็น deterministic: ตัวอย่างชุดเดิมได้ template เดิมเสมอ

## ข้อจำกัดตอนนี้

- ถ้าทุกตัวอย่างมีค่าเหมือนกัน (เช่นสอนด้วยใบแจ้งหนี้ใบเดียวกันซ้ำ) จะถูกมองเป็นข้อความคงที่
- เอกสารที่ layout เปลี่ยนมากในแต่ละใบ ควรใช้ครอปตัวแปรเองร่วมด้วย
- ถ้าตัวอย่างมีใบเดียว ข้อความคงที่ (เช่นเลขภาษีผู้ขาย) จะยังถูกนับเป็นตัวแปร
- ลายมือเขียนยังอ่านไม่ได้ (OCR อ่านได้เฉพาะตัวพิมพ์)
